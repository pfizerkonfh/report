关于本报告的数据可信度

本报告对每一项性能指标都标注了数据来源：实测 表示可在本机复现的真实测量；推演 表示由行为模型或公式计算得出、未经硬件验证；占位 表示外部传入、系统自身不产生该数据。

截至本报告，系统尚无任何一条来自真实机器人硬件的实测数据。所有结论成立范围限于「软件正确性与方法设计」，不适用于「真机性能论证」。

1. 项目背景与问题定义

变电站巡检正从「人工定期巡视」转向「无人化自主巡检」。本系统定位于国网变电站空地协同无人巡检体系中的第 (4) 子项——多智能体任务分配与边缘智能决策系统，负责把一句自然语言任务指令，拆解为可在无人机与机器狗之间分工、在端侧与云端之间分流的执行计划，并保证执行过程可观测、可归因、可恢复。

「空地协同」在本系统中有明确的工程含义：规划完成后，部分子任务交由无人机（UAV）执行，部分交由机器狗（四足机器人）执行，两者共享同一份世界状态与同一套前置校验规则。这与「端-边-云」的计算层级维度相互正交，需要同时建模。

2. 系统总体架构

系统采用单向分层结构：上层产出计划，下层负责执行与度量，层间通过显式的数据契约（Plan / TraceStep / ToolResult / EvalRecord）通信，不共享可变状态。

2.1 双维度正交分配矩阵

系统的一个核心建模决定，是把「谁来做」与「在哪算」拆成两个彼此正交的维度，避免把物理平台与计算层级混为一谈。

3. 关键技术

3.1 长程规划与可恢复执行

规划层用 LangGraph 组织分解流程，产出结构化 Plan（子任务、依赖、工具提示、成功判据、平台）。决策层按 ReAct 范式逐步执行：每一步先做前置校验，再执行工具，最后把观测写回世界状态。

失败时不是简单重试，而是走 Reflexion 归因：把失败症状映射为失败层级（planning / routing / execution / perception），生成可复用的经验条目，并在有上限的重规划中使用。这保证了长链条任务的失败是可解释、可收敛的。

3.2 端-边-云协同路由

每个工具在 RouteHint 中声明计算强度、时延预算、隐私等级与是否具备边缘执行能力。Router 结合 NetworkGovernor 提供的链路状态做选路，云端不可用时按 FallbackStrategy 下沉到边侧，并把降级开销计入时延度量。

诚实说明

链路 RTT 由 random.uniform() 生成，不探测真实网络；端侧 VLA 时延由连乘系数公式计算（MoE ×0.72、蒸馏 ×0.88、INT4 量化 ×0.85、FlashAttention ×0.92、PagedAttention ×0.94），不是真实模型推理测量。这两个模块当前只用于验证路由逻辑本身的正确性。

3.3 空地物理平台建模

引入 Platform 枚举（UAV / DOG / SHARED），Planner 为每个子任务判定执行平台，TraceStep 逐步记录实际执行平台，前端按平台着色渲染 DAG。归一化函数 normalize_platform() 兼容中英文表述，未知表述回落 SHARED 以避免误判。

实测中，真实大模型能正确把「航拍绝缘子」判给无人机、「巡查开关柜」判给机器狗，说明该维度在真实语义理解下是有效的。

3.4 执行通道抽象层（ToolAdapter）

这是本系统从 POC 走向生产的关键解耦。ToolSpec 承载语义契约（Precondition / Effect / Rollback / RouteHint），ToolAdapter 承载执行通道（如何真正做出来）。换真机只需替换 Adapter，Planner / Reasoner / Router / 评测零改动。

通道语义用途
legacy直接调用工具逻辑，零耗时、必然成功算法回归，保证既有行为不变
sim真实墙钟耗时（可加速）、真实超时、可取消、遥测回传、故障注入硬件在环仿真，暴露时序与状态类缺陷
playback按 JSONL 现场记录回放真实时序确定性复现现场问题
ros2ROS2 action 映射骨架，rclpy 可选依赖真机接入位（已留接口，未联调）

真机语义四要素

  • 真实墙钟耗时：无人机相位建模为 自检→起飞→巡航→作业→返航→降落，受 time_scale 加速
  • 真实超时：默认 120s（该数值是仿真实测得出的：一次无人机架次约 47.5s，原 30s 会在返航相位误判超时）
  • 可取消：CancellationToken，取消后进入 cancelled 终止分支立即停机
  • 遥测回传：电量、里程、位置、链路、相位进度

3.5 真实感知层（3DGS 重建数据接入）

系统最初的感知是空缺的——camera 工具返回一个 uuid 假路径。本轮把实验室场景的 3D Gaussian Splatting 重建产物接入，使系统第一次拥有真实数据输入。

四个真实感知工具

工具能力是否真实计算
scene_inspect场景规模、可通行/障碍/未知占比、重建质量是 读取 metrics.json 与栅格统计
map_query指定位置的可通行性及最近可通行点纠偏是 真实占据栅格查询
route_plan8 连通 A* 路径规划（禁穿墙角），返回真实里程是 真实栅格上真实搜索
height_probe点云高度剖面，判断净空或地面起伏是 真实点云统计

坐标系严格沿用原始构建脚本约定：X-Z 为水平面、Y 为竖直轴，栅格索引 occ[ix][iz]，格心换算 xmin + (ix+0.5)×res。因此感知层输出的路径与原有导航管线完全对齐——在真实栅格上重跑 A* 得到 58 格，与原始 build_nav.py 导出的参考路径步数一致。

3.6 可观测性

后端以 SSE 流式下发事件（scene / planning / plan / select / progress / step / replan / reflexion / result / end），前端实时渲染分层 DAG、ReAct 轨迹、平台着色、遥测面板与评测指标，并支持运行中中止。感知层把真实栅格元数据一并下发，前端具备渲染真实地图的数据基础。

4. 解决的问题

下表列出系统在各阶段落地中实际暴露并修复的问题。其中标有「仿真暴露」的几项，在纯 Mock 模式下永远无法被发现——这正是硬件在环仿真层的工程价值所在。

#问题后果修复
1事件钩子误吞状态重置块每次 emit 都清空计划，任务无法推进重置逻辑移回构造函数
2SSE 连接不关闭前端一直卡在「运行中」响应头 Connection: close + 收 end 事件即置位
3端口残留多进程抢答返回旧代码结果，调试误判启动前 netstat 校验单实例
4仿真暴露：默认超时 30s 不足无人机架次约 47.5s，在返航相位被误判超时超时预算改为 120s
5仿真暴露：适配器忽略上下文超时预算超时参数形同虚设改用 ctx.timeout_ms
6仿真暴露：只回传电量不回传语义 Effect后续剪辑/脱敏被前置校验全线阻断，误触发 Reflexion语义 Effect 与物理遥测合并回写
7仿真暴露：急停后仍继续重规划安全事故风险，停机耗时约 95s新增 cancelled 终止分支，停机降至 6.7s
8真实跑测暴露：仿真通道吞掉感知工具的真实计算结果route_plan 明明被调用，最终却是 route_len_m=0.0、观测变成模板文本，感知层形同虚设引入 compute_only 纯计算工具语义：先跑通道取时序（禁静态回写），再跑真实计算覆盖
9Web 控制台暴露：默认初始世界状态为空打开页面点运行即失败：safety_cleared 缺失导致 camera 被硬阻断，2 次重规划后 Reflexion 收场新增 Orchestrator.DEFAULT_WS，把「作业开始前已确认的现场条件」内建为默认值
第 8、9 项的额外意义

这两项是系统在「接上真实数据」和「接上真实用户入口」之后才暴露的。它们说明一个事实：缺陷往往不在算法逻辑里，而在模块边界上——纯计算工具与物理执行工具的语义差异、调用方与被调用方对初始条件的隐含假设。这类问题只有把系统真正跑起来才会出现。

8. 结论

本系统完成了一套面向空地协同巡检的多智能体任务分配与边缘智能决策框架，在三个方向上取得了可验证的进展：

  • 机制上杜绝了工具误调用：以可判定的 Precondition / Effect 语义契约替代自然语言描述，执行前硬校验，实测中真实大模型全程 0 次违例、动作合理度 1.00。
  • 解耦了 POC 与生产的最后一公里：ToolAdapter 把语义契约与执行通道分离，换真机只换 Adapter，决策层零改动——这是此类系统从原型走向部署最容易卡死的环节。
  • 第一次拥有了真实数据输入：3DGS 重建产物经感知层注入世界状态，前置校验首次能判定基于真实数据的条件；真实大模型会自主选用并调用这些工具，感知层已真正参与决策。

同时必须清醒认识其边界：系统尚无真实硬件实测数据，能耗、里程、端侧时延均为模型推演，安全联锁为内置默认值。它的当前价值在于「骨架正确、接口正确、可以长肉」，而非「可直接交付的产品」。

真正使其产生业务价值的关键一步，不是继续堆叠功能，而是接入单台真机（阶段 B）——那将第一次把链路上的推演数字替换为实测数字，系统的性能论证才会真正成立。
