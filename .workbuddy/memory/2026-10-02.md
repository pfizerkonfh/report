## 一、项目可生产性评估（结论：当前是 POC，不能直接上业务）
逐文件核对后确认：
- 7 个工具全部 Mock（camera 返回 uuid 假路径、weather 硬编码"晴"、edit/anonymize 只置 flag）；
- `tools/latency.py` 是连乘系数的**公式仿真**，无真实 VLA 模型/INT4/推理引擎；
- `routing/network.py` 用 `random.uniform()` 模拟 RTT，不探测真实链路；
- 依赖中 **0 个**机器人/硬件/推理框架（无 ros/rclpy/dji/unitree/mavlink/torch/onnx）；
- 无感知模型、无安全联锁（safety_cleared 是手填布尔量）、无持久化/鉴权/审计；
- 评测的 CSAT 是外部传入（`csat or 2.0`），时延是仿真值 —— 测的是仿真系统不是现场。

**用户确认方向：阶段 A —— 硬件在环仿真（HIL）。**

## 二、已完成：ToolAdapter 执行通道抽象层（阶段 A 落地）

换真机只换 Adapter，Planner/Reasoner/Router/评测零改动。

## 三、踩到并修掉的真实问题（有价值，别忘）
1. **默认 30s 超时不够**：一次无人机架次约 49s（自检2+起飞5+往返30+作业8+降落4），30s 会在返航相位误判超时
   → 默认改为 120s。
2. **适配器忽略了调用上下文的超时预算**：`invoke` 用了 `self.timeout_ms` 而非 `ctx.timeout_ms` → 已改为 ctx 优先。
3. **只回传物理遥测、不回传语义 Effect**：导致 `footage` 未写入世界状态，后续 edit/anonymize 被前置校验全线阻断
   并误触发 Reflexion。修法：`AdapterContext.declared_effects` → 语义 Effect 与物理 Effect 合并回写
   （电量等物理事实覆盖语义声明）。sim 与 playback 均已改。
4. **急停后仍在重规划/反思**：真机"急停后继续自主行动"是安全事故。修法：状态图新增 `cancelled` 终止分支，
   `_select` 急停优先、`_execute` 取消后直接停机不进 replan/reflect。
5. 相对导入层级写错：`adapters/*.py` 中 `from ..base import` 应为 `.base`（`..base` 指到了 `tools.base`，引发循环导入）。
6. 录播 `_ensure_loaded` 用 `_loaded` 当成功标志，导致文件缺失后 `health()["ok"]` 仍为 True → 增加 `_ok` 标志。

## 七、价值评估（用户问「有实际价值了吗」）结论
- 判定：**有工程/方法价值，无业务交付价值**。价值需按「证据强度」分层，不能一概而论。
- 真实可兑现：软件正确性（37/37）、SSE 前端可交互、真实 GPT-5.5 规划链路（450ms/p95 190ms）。
- 不可当证据：**VLA 28.5ms 是 `tools/latency.py` 连乘系数估算（非实测）**；电量/里程是行为模型推演；
  CSAT 4.5 是外部传入占位；安全联锁是手填布尔。真实硬件实测数据目前**一条都没有**。
- **关键洞察（跨工作线交汇）**：本系统缺失的正是「感知层」，而用户自身在做 **3DGS 实验室场景重建
  + 占据栅格地图（用于路径规划）**。把 3DGS 重建结果/占据栅格接入 WorldState，
  即可把系统从「纯逻辑仿真」推进为「有真实感知输入的半实物系统」——这是当前性价比最高的价值跃迁路径，
  优先于阶段 B（接真机）。接口点：`core/world_state.py` 的 facts + camera 工具的 footage 语义。

### 发现并修复的**第 8 个真实缺陷**：仿真通道吞掉感知工具的真实计算结果
- 现象：t2 route_plan 明明被调用，最终 facts 却是 `route_ready=False / route_len_m=0.0 / route_steps=0`，
  observation 是模板文本「route_plan完成，任务耗时 1.4s」。
- 根因：adapter 通道只调 `adapter.invoke()`，**从不调 `tool.run()`**；感知工具的真实计算写在 `run()` 里，
  而 adapter 用 `declared_effects=list(tool.effects)` 回写的是**静态声明默认值**（route_ready=False…）。
- 修复：引入「纯计算工具」语义 —— `ToolSpec.compute_only: bool`（默认 False，物理动作类保持 False）；
  `SceneBackedTool.__init__` 统一置 True；`executor._execute_compute_only()` 先跑通道拿时序/遥测
  （传 `declared_effects=[]` 禁止静态回写），再跑真实 `run()` 覆盖，telemetry 以真实计算优先合并。
- 修复后实测：t1 「位置 (-1.33,-2.32) -> 格 (14,16) 为「自由」，可通行」；
  t2 「A* 规划成功：58 格，真实里程 11.73m，途经未知区 0 格」。
- 测试 **65/65 通过**（+3 通道耦合回归）。

## 六、Web 控制台默认跑测失败 —— 第 9 个真实缺陷（已修复）
- 现象：浏览器点运行默认 **failed**：`t_capture` 前置校验阻断 `safety_cleared == True`，
  2 次 replan + 1 次 reflexion 后失败。CLI 脚本不失败是因为脚本里手传了 `ws_init`。
- 根因：`Orchestrator.run()` 在 `ws_init=None` 时用**空 WorldState**，而 camera 等工具的
  Precondition 依赖 `safety_cleared / battery / uav_online` —— 这些是「作业开始前已确认的现场条件」，
  不该由每个调用方重复手传。
- 修复：`Orchestrator.DEFAULT_WS`（battery=100 / safety_cleared=True / edge_capable=True /
  uav_online=True / weather_ok=False / footage,edited,anonymized=False），`run()` 中
  `facts = dict(DEFAULT_WS); facts.update(ws_init or {})` —— 调用方显式传入仍优先。
  注释已标明：真机部署时 safety_cleared/battery/uav_online 必须由安全联锁与机载遥测真实写入。
- 修复后 Web 冒烟（mock + sim time_scale=50）：**success，5 步，40 个 progress 事件，
  12 个 scene_* 事实注入**，p95 1005.9ms / 端到端 3014.5ms，无 replan/reflexion。测试仍 65/65。

### 环境注意事项
- 真实模型调用**必须绕过沙箱**（沙箱会切断 `www.yjsylink.cn:3000` 导致 WinError 10054 /
  「远程主机强迫关闭连接」，4 次重试后抛 RuntimeError）。直连时中转站 ~50% 返回 500，
  指数退避可吸收，单次全链路约 3~4 分钟。
- `RunResult` 字段是 `metrics`（不是 evaluation）；真实 LLM 返回的 `plan.subtasks` 可能是**纯字符串列表**
  （t1..t6），打印计划须兼容 str 与 SubTask 两种形态。
