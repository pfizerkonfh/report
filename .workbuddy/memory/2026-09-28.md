## 关键教训（第二次失败后才确认）
- 预览面板**连不到本地 HTTP 服务**，且**预览环境的 ES Module / importmap 不生效** → 之前两个版本（gaussian-splats-3d、three.js Points）整段模块脚本不执行：统计/画廊为空、按钮点了没反应。
- 根本解法：**不要在预览里跑浏览器端 3D/WebGL/ES Module**。改用 **服务器侧渲染 + 完全自包含单文件 HTML**：
  - `render_showcase.py`：matplotlib(Agg) 离屏渲染点云 → 36 帧旋转 GIF（765KB）+ 6 张多角度静帧 PNG。
  - `generate_showcase.py`：把 GIF/静帧/渲染对比图（render+gt，base64 内嵌）+ 指标 全部打进 `viewer/showcase.html`（5.25MB，零外部依赖、无 fetch/import/http）。
  - 交付时**用本地文件路径** `present_files([本地路径])`，不要用 http://localhost URL，否则预览代理解析不到资源。
- 此"服务器端渲染成图 + 自包含 HTML"模式，是预览环境显示 3D/可视化结果的可靠兜底方案，可复用到其他无法在预览跑 WebGL 的场景。

## 寻路能力演示（地图→导航）
- `build_nav.py`：点云投影 (X,Z) 网格（res=0.2m）→ 每格"高于地面(10%分位) 0.6m 的点数≥3"判障碍 → **相机轨迹经过的格子强制为自由**（关键！否则自由空间碎片化、A\* 失败）→ 障碍膨胀 1 格再恢复轨迹走廊。
- 起终点：起点=轨迹首格，终点=轨迹上离起点最远的格（轨迹是闭环，首尾同格会导致路径长度 1）。
- A\*(8 连通+禁穿墙角) 规划出 58 格路径：蓝线=探索轨迹 vs 橙线=规划捷径，说服力强。
- 产物：nav_topdown.png（带图例/比例尺）、nav_path.gif（智能体沿路径动画 58 帧）、nav_3d.gif（路径贴回点云旋转）。
- 点云与 cameras.json **同一坐标系**，但少数离群高斯把极值拉到 69m——必须按 0.5%~99.5% 分位裁剪后再建图。
