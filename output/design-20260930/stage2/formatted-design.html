一、项目总体设计概述

1.1 背景与目标对齐

本项目依托人工智能、机器人控制、边缘计算与多模态感知，构建以无人机（UAV）与机器狗（UGV）为主体的空地协同智能巡检系统。依据项目背景所列 11 项核心目标，本系统设计覆盖关系如下：

目标编号目标内容本设计覆盖关系
（1）多模态空地感知与协同控制调度层直接支撑
（2）轻量大模型边缘部署边缘决策层支撑
（3）空地协同三维建图与多路径规划与决策层联动
（4）多智能体任务分配与边缘智能决策本设计核心
（5）~（11）数据库 / 缺陷识别 / 传感器接入 / 系统验证 / 文档横切支撑

1.2 系统设计原则

  • 边缘优先（Edge-First）：实时控制与隐私敏感任务留在端侧，仅把重算力/大模型任务下沉云端。
  • 目标可证（Goal-Provable）：每个 Agent 动作都可追溯到全局目标与前置/后置条件，杜绝"丢失目标"。
  • 可观测（Observable）：全链路 trace_id 贯通规划层、动作层、端侧推理层，便于 badcase 归因。
  • 可回退（Degradable）：任一环节失败均有兜底路径，网络抖动下系统降级而非崩溃。

1.3 文档范围

本文重点解决四类工程问题，并给出架构、规范、机制与度量方法；其余目标在第 4 章做支撑性简述。

2.2 多智能体协同拓扑

定义五类 Agent 角色，通过消息总线与共享世界状态（World State）协作：

  • 规划 Agent（Planner）：将用户跨模块任务分解为带里程碑的有向无环图（DAG），不调用工具。
  • 调度 Agent（Dispatcher）：依据路由协议把子任务派发给边/云执行体，并管理回退。
  • 推理 Agent（Reasoner）：按当前状态 + 计划上下文选择工具、校验前置条件、执行并观测效果。
  • 感知 Agent（Perceiver）：封装多模态传感与建图能力，对外暴露标准化工具。
  • 决策 Agent（Decider）：边缘侧运行轻量模型，完成实时控制与异常初判。

2.3 数据与控制流

用户指令 → 规划 Agent（DAG）→ 调度 Agent（路由）→ 推理/决策 Agent（执行）→ 感知/控制回路 → 结果回流评测层。全程携带 trace_id，三层指标在评测层汇聚。

三、核心：多智能体任务分配与边缘智能决策系统

3.1 问题一：Agent 长程规划失败改造方案

3.1.1 问题刻画

用户用中文下发跨模块任务（如"帮我把这一天的素材拍好剪成短片并去除人脸"），Agent 拆成 5–8 步后常出现：①中段丢失全局目标（subgoal drift）；②工具误调用（参数错、时序错、对象错）。根因是"一个 LLM 同时承担长程规划与逐步执行"，缺乏状态约束与分层校验。

3.1.2 架构改造：全局目标锚定 + 分层认知

引入 Goal Registry（目标寄存器） 与 World State（世界状态） 两个共享结构：

  • Goal Registry 保存任务终态约束（如"产出带人脸模糊的成片"），每个子步骤执行前都做一次"是否仍服务最终目标"的一致性校验。
  • World State 以结构化 JSON 维护环境/资源/已完成子目标，工具调用前后以 Precondition/Effect 更新它。

3.1.3 工具描述规范（Precondition / Effect 语义）

每个工具在注册时除 description 外，必须声明 preconditions（调用前必须为真的状态断言）与 effects（调用后发生的状态变化），并可选 rollback。示例如下：

{
  "name": "face_blur",
  "description": "对输入视频逐帧检测并模糊人脸区域",
  "inputs": { "video_path": "string", "strength": "float" },
  "preconditions": [
    "world.media.input_video_exists == true",
    "world.media.video_format in ['mp4','mov']"
  ],
  "effects": [
    "world.media.output_video_path = <generated>",
    "world.media.face_blurred = true"
  ],
  "rollback": "delete(world.media.output_video_path)",
  "globally_safe": true
}
运行时约束
执行前做 Precondition 检查：不满足则阻断调用并升级给 Planner 重新规划，而非擅自替换工具。Effect 在执行后回写 World State，使后续步骤基于真实状态决策，避免"幻觉式"工具链。

3.1.4 Planner / Reasoner 分层设计

  • Planner（长程）：仅做分解与排程，输出 DAG（节点=子目标，边=依赖），不接触具体工具参数；每节点附 success_criteria。
  • Reasoner（逐步）：在每个节点，结合 Goal Registry + World State，选择工具、填参、校验 Precondition、执行、观测 Effect、更新状态；若 Precondition 不满足或 Effect 与 success_criteria 不符，则回退到 Planner 触发局部重规划（re-plan），而非整任务重来。

这种"规划与执行解耦 + 状态校验闭环"从结构上消除目标丢失与误调用。

3.1.5 ReAct / Reflexion 机制应用

  • ReAct（推理-行动循环）：在 Reasoner 层落地。每步 = Thought（基于 World State 推理）→ Action（选工具+参数）→ Observation（读取 Effect/返回）。循环直到节点 success_criteria 满足。Thought 必须显式引用 Goal Registry 以保持目标锚定。
  • Reflexion（反思记忆）：任务失败后，Agent 回放轨迹（trace）生成自然语言 self-critique 与 lessons，写入 Experience Buffer（经验缓冲）。下次同类任务，Planner 读取相关经验优化分解策略；对反复出现的工具误调用，自动强化其 Precondition 检查。即"离线反思 → 在线复用"，形成持续改进闭环。

3.1.6 预期收益

收益预期
  • 长程任务规划成功率显著提升（目标漂移与误调用被结构化阻断）。
  • 工具误调用率下降（Precondition 前置拦截 + Reflexion 经验闭环）。
  • 失败可解释、可定位（trace + Goal Registry 一致性 + Experience Buffer）。

3.2 问题二：端侧 VLA 模型延迟优化

3.2.1 问题刻画

端侧约 3B 参数 VLA 模型（INT4 量化）在低算力芯片上单步推理延迟达 65ms，而控制环要求 20Hz（周期 50ms），已超出预算，导致控制环降频、响应迟滞。需从模型结构、量化、推理算子三层叠加优化，把端到端单步压到 <50ms。

3.2.2 模型结构层面

  • MoE（混合专家）稀疏化：将前馈层改为专家路由，每 token 仅激活 top-k 专家，等效计算量显著下降而容量保持；配合负载均衡 loss 防止路由塌缩。
  • 知识蒸馏：用 7B 教师 VLA 蒸馏 3B 学生（含动作头蒸馏），在参数量不变下提升精度，从而允许更激进的量化/剪枝而不损性能；同时可对视觉编码器做结构化剪枝。

3.2.3 量化算法层面

  • AWQ（激活感知权重量化）：以激活分布为保护信号，对"显著权重"做通道级缩放保护，4-bit 权重下精度损失远小于 RTN；可直接承接现有 INT4 部署并恢复精度。
  • SmoothQuant（平滑量化）：把激活离群点向权重迁移，使权重与激活均可做 W8A8，消除 INT4 反量化开销与数值不稳定，进一步压缩单步时延。二者可分层组合：注意力层用 SmoothQuant(W8A8)，其余层用 AWQ(INT4)。

3.2.4 推理算子层面

  • FlashAttention：IO 感知的注意力实现，将 Q/K/V 分块在 SRAM 计算、大幅减少 HBM 读写，降低注意力延迟与显存占用。
  • PagedAttention：KV Cache 按页管理，支持连续批处理（continuous batching）与碎片复用，提升边侧有限显存下的吞吐与稳定性，间接降低尾延迟。

3.2.5 端到端时延度量方法

建立统一时延基准（latency harness）：固定输入序列长度，分别测量 prefill 延迟、decode 单步延迟、感知→推理→执行 端到端控制环延迟，以 p50/p95/p99 汇报，并监控控制环实际频率。

优化层手段预期单步延迟控制环频率
基线INT4 3B65ms<16Hz
+ 量化AWQ(INT4)+SmoothQuant(W8A8)~52ms~19Hz
+ 算子FlashAttention + PagedAttention~44ms~22Hz
+ 结构MoE 稀疏 + 蒸馏<40ms≥25Hz
度量纪律：每次改动只变动一层并回归基准，确认 p99 < 50ms 且控制环频率 ≥ 20Hz 方可合入。

3.3 问题三：端-边-云任务路由协议

3.3.1 路由决策框架

在调度 Agent 内嵌 RouteDecision 判定：先判隐私/本地约束，再判时延预算与边侧算力，最后判算力强度与是否需大模型。

3.3.2 可落地路由协议（字段定义）

{
  "task_id": "uuid",
  "task_type": "vla_control | editing | reconstruction | llm_reason | asr ...",
  "payload_size_mb": 12.5,
  "latency_budget_ms": 50,
  "compute_intensity": "low|mid|high",
  "privacy_level": "local|normal",
  "requires_cloud_model": false,
  "edge_capable": true,
  "network_rtt_ms": 30,
  "fallback_plan": "edge_cache|cloud_escalate|degrade_cmd"
}

判定树：

  1. privacy_level == local → 边侧。
  2. latency_budget_ms < 边缘阈值 且 edge_capable → 边侧。
  3. compute_intensity == high 或 requires_cloud_model == true → 云端。
  4. 其余 → 边侧（默认边缘优先）。

3.3.3 边侧 vs 云端任务划分

落点任务类型理由
边侧VLA 实时控制、局部避障、轻量 ASR、人脸模糊（轻）、本地 NL 问答、异常初判实时/隐私/低算力
云端3DGS 重建、跨天素材剪辑、大模型推理、模型训练/微调、跨站知识检索重算力/大模型

3.3.4 失败回退与网络抖动兜底

  • 边→云升级：边侧执行失败（超时/资源不足）自动 cloud_escalate，携带中间结果避免重算。
  • 云→边降级：云端不可达时下发轻量边侧模型或返回缓存结果（edge_cache），保证基本能力。
  • 网络抖动治理：①stale-state hold——超时沿用上一帧"last-good"指令，避免失控；②自适应控制频率，抖动时降频保稳；③指数退避 + 抖动（jitter）重连；④边缘缓存高频结果；⑤采用 QUIC/HTTP3 抗丢包；⑥"网络质量 governor"动态降级非关键任务。

3.4 问题四：统一评测体系

3.4.1 三层链路评测口径统一

规划层、Agent 动作层、端侧推理层当前指标互不相通。统一以 task（一次用户任务） 为根，挂 trace_id，三层共享同一标识，指标在评测层聚合，支持跨层归因。

3.4.2 统一评测指标体系

维度指标定义/口径
规划成功率plan_success_rate长程任务完整达成率；子目标完成数/总数
Agent 动作合理度action_validity工具 Precondition 违例率、动作与 success_criteria 吻合度（奖励模型/人工 rubric）
端到端时延e2e_latency控制环 p50/p95/p99 与任务总耗时
用户满意度csat / nps任务达成主观评分、净推荐值

跨层归因矩阵（badcase → 根因层）：

现象规划成功率动作合理度时延用户满意度根因层
任务半途而废低高高低规划层
调用错工具高低高低动作层
卡顿迟滞高高低低端侧推理层
达成但不满意高高高低需求/交互层

3.4.3 离线回放 + 在线 A/B 测试闭环

  • 离线回放：把轨迹（state/action/observation/latency/outcome）存入回放缓冲，用确定性 harness 复现 badcase，逐层二分定位根因层，做版本回归。
  • 在线 A/B：对路由策略/模型版本做影子模式（shadow）与 A/B 分流，采集统一指标；设护栏——若 p99 时延超阈或成功率跌幅超阈值，自动回滚到基线。
  • 闭环：离线回放产出假设 → 在线 A/B 验证 → 护栏保护 → 经验回流 Experience Buffer（呼应 3.1.5），形成持续评测-优化闭环。

四、对其它项目目标的支撑设计（简述）

  • （1）协同控制：调度层任务分配算法（紧急度/设备状态/覆盖范围加权）直接驱动双平台时间协同。

五、系统集成、里程碑与验证计划

  • M1（架构与规范）：完成四层架构、Agent 角色定义、工具 Precondition/Effect 规范、路由协议 v1。
  • M2（长程规划改造）：Planner/Reasoner 分层 + Goal Registry + ReAct/Reflexion 闭环，规划成功率达标。
  • M3（端侧时延优化）：MoE+蒸馏+AWQ/SmoothQuant+Flash/PagedAttention 落地，控制环 ≥20Hz。
  • M4（路由与回退）：端-边-云路由协议上线，含抖动治理与回退演练。
  • M5（统一评测）：三层指标贯通 + 离线回放 + 在线 A/B 护栏，输出 badcase 归因看板。
  • M6（现场验证）：变电站部署，形成可复制方案。
关键风险
边侧算力不足 → 以 MoE 稀疏与量化叠加缓解；网络不稳 → 以 3.3.4 兜底；长程规划漂移 → 以 3.1 分层与反思闭环缓解。

六、小结

本文以"边缘优先、目标可证、可观测、可回退"为原则，给出了多智能体任务分配与边缘智能决策系统的完整设计：用 Planner/Reasoner 分层 + Precondition/Effect + ReAct/Reflexion 根治长程规划失败；用结构/量化/算子三层优化压低端侧 VLA 时延；用可落地路由协议和抖动治理贯通端-边-云；用统一指标 + 离线回放 + 在线 A/B 实现跨层评测与归因，整体支撑空地协同变电巡检的"机巡+智检"升级。
